## 2. Delivered Surface

### R1 — `tethys-api`

- One `pub trait <Namespace>Api: Send + Sync` per `architecture.md` §12.1 namespace, each with the
  same default bodies and byte-identical `Unimplemented` strings as before:
  `HostApi`, `WorkspaceApi`, `AgentApi`, `ThreadApi`, `EventsApi`, `PermissionApi`, `GitApi`,
  `SearchApi`, `CommandsApi`, `TerminalApi`, plus the existing `McpApi` / `SkillsApi`.
- `bench.rs` holds the non-§12.1 `BenchApi` (`generate_synthetic_diff`), so a future deletion is
  one file.
- `TethysApi` is a marker trait whose supertraits are the namespace traits, satisfied by a blanket
  impl. `Core` needs no explicit `impl TethysApi`; it implements each sub-trait.
- `tethys-core`'s single `impl TethysApi for Core` split into
  `crates/tethys-core/src/api/{host,workspace,agent,thread,events,permission,git,search,commands,terminal,bench}.rs`
  with `api/mod.rs`; `lib.rs` keeps `Core`, `CorePaths`, the constructors, the private helpers and
  `mod api;`.
- `tests/stubs_test.rs` split into `tests/stubs/<namespace>.rs` over a shared `MinimalApi` fixture
  in `tests/stubs/mod.rs`; 13 tests assert every default-bodied `Unimplemented` string (and that
  `MinimalApi` still satisfies `TethysApi` via the blanket impl).

### R2 — Tauri host

- `apps/desktop/src-tauri/src/commands/mod.rs` defines `CoreState` and `stub_cmd!`, and re-exports
  each namespace module. `commands.rs` is deleted.
- Namespace modules: `host`, `workspace`, `agent`, `thread`, `events`, `permission`, `git`,
  `search`, `mcp`, `skills`, `commands_ns`, `terminal`, `bench`. Each imports only the sub-trait(s)
  it forwards to.
- The `commands` namespace module is `commands_ns.rs`, avoiding a `commands::commands` path and
  kept consistent with the client's `commands` module.

### R3 — `@tethys/client`

- `src/transport.ts` owns `Transport`, `ClientOptions`, the `Call` type and the `createCall`
  factory. `src/namespaces/<namespace>.ts` returns one namespace object each; `index.ts` composes
  them and keeps the flat back-compat helpers and the whole `export type { … }` block.
- `run_stream_benchmark`'s `Channel` usage and `getSyntheticDiff` live in `namespaces/bench.ts`.
- Every namespace file carries its Wave-2 owner and a `TODO(<chunk>): type the arguments against
  tethys-api` where the wrappers are still `call<void>()` — `thread` (C), `agent` (E), `events`
  and `permission` (A), `workspace`'s `list/add/remove/settings*/status` (F), `mcp.health` (D),

- `src/surface.assert.ts` asserts, at typecheck time, that `TethysClient` still extends an

## 4. Decisions

- **`generate_handler!` fallback taken.** `tauri-macros`' `generate_handler` is a proc-macro that
  parses a comma-separated list of command paths (`command::handler::Handler` →
  `parse_terminated(CommandDef::parse)`, where `CommandDef` parses a `syn::Path`). A
  `macro_rules!` invocation in its argument list is not a `Path`, so per-namespace list macros
  cannot be expanded into it. The plan's documented fallback is used: the list stays in `lib.rs`,
  strictly namespace-grouped with one blank-line-separated block per owner, so a feature chunk's
  edit is confined to its own block. Per-namespace command *definitions* are still split, which is
  the larger win.
- **`TethysApi` is a marker trait with a blanket impl.** `impl<T> TethysApi for T where T: … + every
  sub-trait`. `Core` has no explicit `impl TethysApi`; coherence is clean because `TethysApi` has
  no items. Callers that previously imported only `TethysApi` now import the sub-trait they call
  through (`TethysApi` in scope alone does not bring supertrait methods into method resolution
  across crates) — a `use`-list-only change, as the plan anticipated.
- **`WorkspaceApi`, `PermissionApi` and `TerminalApi` need explicit empty impls for `Core`.**
  Their methods are all defaulted, but `Core` must still implement each trait to satisfy the
  blanket `TethysApi` bound; the plan's api-file list omitted them.
- **The client's argument-passing bug is untouched.** `thread.create`, `agent.*`, `events.*`,
  `permission.*`, `workspace.list/add/remove/settings*/status`, `mcp.health` and `terminal.*` keep
  their `call<void>()` signatures, with `TODO(<chunk>)` headers naming the owner who types them.
- **`markdown-it` + `dompurify`.** A's plan names `markdown-it` and requires an allow-list
  sanitizer in this batch but does not name one; DOMPurify is the standard allow-list choice and is
  swappable behind the same async API.
- **`@tanstack/react-form` dropped; `@tanstack/react-table` kept.** E's D5 answer is "neither for
  MVP"; D's plan (D7 reversal) claims `react-table` for the MCP matrix. The open question is
  resolved by the sibling plans rather than a new decision.

## 6. Limitations / Follow-ups

- `git.rs` (189 lines) and `mcp.rs` (173 lines) exceed the plan's ~120-line target because those
  namespaces genuinely have 15 and 12 typed commands; splitting further would break the
  one-file-per-namespace rule that is the point of the seam.
- `TethysApi` in scope alone no longer resolves supertrait methods across crates. This is a
  deliberate consequence of the split; each caller imports the trait it uses.
- The `invoke_handler!` list is still a single file (fallback). Resolving it would need a Tauri
  change to accept macro-expanded input; recorded in the plan's risks.
- `packages/client`'s surface guard is typecheck-only (per R3's allowance), so it fails on
  `pnpm typecheck`, not `pnpm test`; the package still reports "no tests yet".
- The two Tauri plugins are added on the **Rust** side only (`tauri-plugin-notification` /
  `tauri-plugin-dialog` plus their capability entries), as U4 scopes them. The matching frontend
  packages (`@tauri-apps/plugin-notification`, `@tauri-apps/plugin-dialog`) are not named by this
  plan's npm list, so worktrees A (M1.8 notifications) and F (M1.16 folder picker) add them when
  they wire the usage, via §1.2's per-chunk lock PR if needed.
- Deferred as planned: deleting the client's camel/snake aliases; `tauri-specta` bindings;
  splitting `tethys-core/src/lib.rs`'s non-API helpers out of the crate root.
