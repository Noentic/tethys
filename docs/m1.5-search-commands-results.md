## 2. Delivered Surface

- `tethys-search`: `SearchIndexManager` keyed by worktree root — lazy open (no 30 s stall),
  bounded `WARM_DEADLINE`, `wait_ready`, `invalidate`, `drop_index`; `SearchError`
  (`IndexWarming`, `Io`, `Picker`). `WorktreeSearchIndex` now uses `fuzzy_search_mixed` and
  reports `SearchItem.is_dir`.
- `tethys-core::composer`:
  - `commands::{list_commands, expand_command}` — flat `~/.tethys/commands` + `<repo>/.tethys/commands`,
    project shadows global; `{{args}}` substitution or newline append; nested `$`/`@` resolved in one pass.
  - `skills::{skill_reference, SkillCandidate}` — plaintext instruction naming the skill, its frontmatter
    description, and `SKILL.md` path; the body is never read.
  - `paths::path_reference` — plaintext `@<relative-path>` plus `name`/`is_dir`/`mime`/`size` metadata;
    root-jailed; `:range` suffix stripped (CMP‑06 deferred).
- `tethys-schema`: `search.rs` (`SearchItem.is_dir`), `composer.rs` (`CommandInfo`, `CommandScope`,
  `ReferenceKind`, `ComposerReference`, `ExpandedCommand`); bindings regenerated.
- IPC: `search.files(projectRoot, query, limit)`, `commands.list(projectRoot?)`,
  `commands.expand(command, argsText, projectRoot?)` wired through `tethys-api`, the Tauri host,
  and `@tethys/client`.
- `tethys-core` drops the global search singleton; `git.worktree_remove`/`worktree_archive` drop
  the root's index.

---

## 3. Reference-only policy

`/` command bodies still expand (CMP‑01), but `$` skill bodies and `@` file contents are never
injected. Every resolved block is plaintext, identical for every agent regardless of capability;
structured metadata rides on `ExpandedCommand.references` for chips/icons only. See
`docs/prd.md` CMP‑01/03/04 and `docs/architecture.md` §7.8.

## 5. Limitations / Follow-ups

- Line ranges on `@` tags (CMP‑06) are parsed and stripped, not carried; M2.7.
- Composer UI (chips, popups, queue) is M1.10; this milestone is backend only.
- Frecency persistence across sessions is not implemented (FFF keeps it in memory); not P0.
- Skill resolution requires M1.4 trust: only `enabled && trusted` skills become candidates.
- The warm deadline (150 ms) is calibrated against the S0.5 number; recalibrate if cold-start
  scans on very large repos start surfacing `IndexWarming` in practice.
