## 2. Delivered Surface

### Rust

- **Trust store (`tethys-store`).** `workspace_trust.rs` (`TrustRow`, `upsert_trust`/`trust`/`delete_trust`/`list_trust`) plus async `EventStore` wrappers and `schema::list_workspaces`. No migration edit: `0005` pre-allocated the table (D14). The `UNIQUE(resolved_path, host)` index rejects a second workspace id for the same folder; `ON CONFLICT(workspace_id)` makes a re-add update one row.
- **Trust port (`tethys-core/src/workspace_trust.rs`).** `WorkspaceTrust` (`grant`/`trust`/`revoke`/`list`) with `StoreWorkspaceTrust` and a `StaticTrust` test impl; `row_matches`/`trust_state` compare the canonicalized path and the re-read `origin` URL; `trust_state_async` runs the read-only git comparison off the async worker.
- **Capability resolver (`workspace/capability.rs`).** Pure `resolve(root, CapabilityInputs)` and `resolve_folder(root)`; `vcs_for_root` classifies none / git-local / git-remote(host); `max_concurrent_sessions_for_vcs` is `Some(1)` iff no VCS. `Core::resolve_capabilities` caches per id and `invalidate_capabilities` drops one entry; wired on trust grant/revoke and in-place `git init`.
- **Roots tightening (`workspace_roots.rs`).** `TrustFilteredRoots` wraps the inner resolver and the trust port; `trust_status` distinguishes `Trusted`/`Untrusted`/`Changed`. `Core::open`/`with_store` build it and set it on `ThreadSessions`.
- **Concurrency guard (`thread_session.rs`).** The one `create` site resolves the cap through the shared rule and refuses a second live session with `ApiError::ConcurrencyLimit`.
- **Typed namespace.** `tethys-schema/src/catalog.rs` (`WorkspaceListItem`, `WorkspaceSessionSummary`, `TrustGrant`, `TrustScope`, `WorkspaceTrustState`) registered in `registered_types()`; typed `WorkspaceApi`; `Core` impl (`list`/`add`/`remove`/`status`/`capabilities`); Tauri commands; typed client wrappers; `pnpm codegen` regenerated the bindings.

### TypeScript

- **`@tethys/state/workspaces.ts`.** Catalog view model + fixture, `useWorkspaceList`/`useWorkspaceCapabilities` (named real sources per D12), the session-status mapping, and the pure chip slot-priority / field-drop / filter-sort functions.
- **`@tethys/features/workspaces`.** `workspace-card`, `session-topology-canvas` (both modes as one accessible `role="img"` SVG), `session-item-chip`, `session-item-row`, `workspace-peek-drawer` (two tabs, deep-link, focus trap), `workspace-trust-dialog`, `workspaces-view`.
- **`@tethys/features/settings/general/trusted-folders`.** Extracted revoke list, mounted in `settings.general.tsx`.
- **Route mounts.** `workspaces.tsx` forwards navigation only.

## 3. Review Fixes

- **Async-runtime blocking.** The first cut ran `git` subprocesses synchronously inside async fns (`TrustFilteredRoots::root`, `trust_status`, `workspace_list`, `workspace_status`, `thread.create`, `workspace_add`). All reads now go through `tokio::task::spawn_blocking` (`trust_state_async`, the create guard, the `workspace_add` probes), matching the repo's `blocking(...)` convention; the trust comparison fails closed (`Untrusted`) on a join error.
- **Prototype-chain bug.** `sessionStatusKey` used `state in threadStateToStatusKey`, which matched `"toString"`/`"constructor"`; switched to `Object.hasOwn`, with a regression test.
- **Test fidelity.** The untrusted-row test was widened to the full namespace set via a shared helper; added the U3 spawn-gate test, the U4 delete-frees-cap case, and a U2 assertion that proves a genuine cache hit (a stale read with no invalidation).

## 4. Deviations / Decisions Recorded

- `workspace.settings_get` / `workspace.settings_set` stay nullary `Unimplemented` stubs: they are not part of the trust flow and M1.6d owns their shape.
- `restore` at the workspace level means "checkpoints are possible for this folder" (git present), per the plan's assumption; the per-session Provider-`initialize` downgrade is worktree B's capability hook.
- Revoke deletes the trust row only (the plan's open question); it does not force-archive live threads, which stays on M1.2's delete path.
- The U5 "`workspace.add` is the one path-taking method" criterion is enforced by the trait signatures rather than a grep test.

## 6. Limitations / Follow-ups

- **Folder picker + pre-trust VCS inspection are not wired at the route mount.** `WorkspacesView` exposes `pickFolder` / `inspectPath` seams (D12), and the add flow is tested with them injected. Wiring needs the `@tauri-apps/plugin-dialog` frontend package (assigned to F by the M1.6d results note) **and** a read-only path-inspection API — the plan allocated no `workspace.inspect`, and `workspace.add` is deliberately the only path-taking method (principle 8). Land both together in a follow-up lock PR.
- **The catalog renders the D12 fixture default.** `workspace.list` is the named swap point; worktree C consumes it at the Wave 2 checkpoint.
- **`workspace-card`'s `onInitGit` is not passed by the view.** The `git-init-upsell-chip` renders on non-git cards; the functional init path is the trust dialog's `Initialize git now` checkbox.
- **Capability cache invalidation on checkpoint writes** is exposed (`Core::invalidate_capabilities`) but not yet called from M1.3's checkpoint path; the resolver is ready for that wiring.
