## 1. Context & Scope

Tethys supports three classes of agent execution (PRD §2.2):
- **Class A — ACP-native:** Vendor's own binary speaking the Agent Client Protocol directly.
- **Class B — ACP adapter:** A separate adapter wrapping the vendor's CLI or SDK into ACP.
- **Class C — Native terminal:** The vendor's unmodified CLI running inside an embedded terminal emulator.

Because coding agents interact with third-party vendor platforms, authentication schemes, and usage policies, Tethys maintains an explicit **Vendor Compliance Matrix**. This provides clear product guidance for users and ensures Tethys respects vendor terms of service without acting as unauthorized middleware.

## 3. Resolution of Product Decision PD-1

### Decision Question
*What is the sign-in guidance and onboarding flow for Claude when running via an ACP adapter (Class B)?*

### Decision Outcome: **API Key by Default with Context Notice**
1. **Default Onboarding:**
   - During agent profile creation for Claude via Class B adapter, Tethys presents **API Key (`ANTHROPIC_API_KEY`)** as the recommended, default authentication path.
2. **Subscription Notice:**
   - If the user selects consumer sign-in or web session credentials, Tethys displays an informative disclaimer:
     > *"Using consumer subscription sign-in with third-party wrappers may be subject to vendor policy restrictions. For enterprise and professional workflows, an API key is recommended."*
3. **No Secret Scraping:**
   - Tethys never scrapes session cookies or intercepts subscription tokens directly. Sign-in delegations invoke the adapter's own native prompt or delegate to the environment variable.

**Status: CLOSED (PD-1 resolved).**

## 4. Plan for Product Decision PD-2 (Class C Terminal Hosting)

### Objective
Determine which vendors accept unmodified CLI hosting (Class C) in an embedded terminal prior to shipping Phase 1 / V1.

### Agreed Confirmation Plan:
1. **P1 Gate Requirement:** Prior to enabling Class C profiles in production builds:
   - For each vendor CLI targeted for Class C (Claude Code, OpenAI Codex, Kiro CLI), conduct a formal review against the vendor's developer license agreements.
   - Verify that running the CLI in a pseudo-terminal (PTY) without payload tampering qualifies as standard environment execution (comparable to running inside VS Code Integrated Terminal, Ghostty, or iTerm2).
2. **Feature Flagging:**
   - Class C profiles are guarded by `feature_flags.enable_class_c` (default `false` in MVP until vendor review sign-off).
3. **Vendor Re-verification Cadence:**
   - The compliance matrix must be reviewed and re-verified at least once every 30 days during active release cycles.
