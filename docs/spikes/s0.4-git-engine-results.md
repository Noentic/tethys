## 1. Context & Architecture

Coding agents frequently experiment with multi-file edits across turns. Tethys provides instant checkpoints (`refs/tethys/checkpoints/<thread>/<turn>`) allowing users to undo, review, or fork from any turn without polluting user Git branches or running commit hooks.

Per `ARCHITECTURE.md §10.3`, checkpoints must:
1. Never touch the user's active branch or working index (`.git/index`).
2. Complete in under 1 second even in large codebases with 100,000+ files.
3. Support zero-loss restore.

---

## 2. Benchmark Methodology

The benchmark in [`crates/tethys-core/tests/git_benchmark.rs`](file:///home/woshi/code/tethys/crates/tethys-core/tests/git_benchmark.rs):
1. **Repository Generation:** Initialized a Git repository containing **100,000 tracked files** across 50 subdirectories (`pkg_00` to `pkg_49`) and committed initial `HEAD`.
2. **Turn Modifications:** Simulated typical turn edits:
   - Modified 5 tracked files.
   - Added 2 new files.
   - Deleted 1 tracked file.
3. **Temp-Index Pipeline Execution:**
   - Evaluated `GitEngine::create_checkpoint()` using temporary index file (`.git/tethys_index_<thread>_<turn>`).
   - Copied existing stat cache to preserve sub-second update checks.
   - Generated checkpoint commit and updated `refs/tethys/checkpoints/<thread>/<turn>`.
   - Verified that user's active working tree branch remains untouched.
   - Restored working tree to previous state via `GitEngine::restore_checkpoint()`.

## 4. Resolution of Architecture Decision AD-5

### Decision Question
*Which Git library architecture should Tethys use for mutations and reads?*
- **Option A:** Pure `git2` / libgit2.
- **Option B:** Git CLI only.
- **Option C:** `gix` (Gitoxide) for reads + Git CLI for mutations (proposed).

### Evaluation
1. **Mutations via CLI:** Using the system Git CLI for mutations ensures user hooks, signing configs (GPG/SSH), credential helpers, worktree isolation, and LFS behave identically to the user's terminal environment.
2. **Reads via `gix` & Stat Cache:** Pure CLI status checks across 100k files without cache can incur full directory walks; copying the index stat cache and using `gix` for high-frequency tree and status inspections achieves sub-150ms latency.

### Decision Outcome: **Option C (`gix` for reads + Git CLI for mutations)**
Tethys adopts **Option C**. All checkpoint creation, worktree creation, commits, and branch operations execute via the Git CLI with temporary index isolation; high-frequency read pipelines query `gix` with CLI porcelain fallback.

**Status: CLOSED (AD-5 resolved).**
