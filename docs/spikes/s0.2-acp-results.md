## 1. Context & Architecture

The Agent Client Protocol (ACP) standardizes editor-to-agent interactions. While ACP v1 is stable, ACP v2 introduces:
- Acknowledgement-only `session/prompt` with asynchronous `session/state_update` notifications (`running`, `idle`, `requires_action`).
- Fine-grained upsert and patch semantics (`session/patch`, `git_patch`).
- Native session resume with replay from history start (`session/resume { replayFrom: "start" }`).
- Removal of client-provided filesystem/terminal execution in favor of MCP.

Per `ARCHITECTURE.md §7.1` and `AD-8`, Tethys implements a **v2-shaped internal event model** (`TurnEventBody`, `Patch<T>`), with an adapter translating legacy v1 notifications into this normalized representation.

## 3. Resolution of Architecture Decision AD-8

### Decision Question
*How should Tethys handle the transition between ACP v1 and ACP v2?*
- **Option A:** v1 only for MVP, defer v2.
- **Option B:** v2 only, breaking compatibility with v1 agents.
- **Option C:** v1 + v2 side-by-side, v2-shaped internal model, v2 behind feature flag (proposed).

### Decision Outcome: **Option C (v1 + v2 side-by-side, v2-shaped internal model)**
- Tethys sends `protocolVersion: 2` when `feature_flags.acp_v2` is active, otherwise negotiates `protocolVersion: 1`.
- All domain modules above the transport seam (`tethys-core`, SQLite event log, TanStack Store) operate exclusively on the v2-shaped normalized model.
- Retiring v1 in future phases will require deleting only the v1 translation adapter, with zero changes to product UI or event persistence.

**Status: CLOSED (AD-8 resolved).**
