## 1. Context & Scope

Coding agents generate continuous streaming output, tool updates, and large diffs across multiple threads. Spike S0.1 evaluates:
1. **IPC Streaming Throughput:** Delivering 200-byte small chunks across 8 concurrent streams using Tauri v2 channels and Tokio message queues.
2. **Webview State Reducers & Batching:** Using `@tanstack/store` with `requestAnimationFrame` (rAF) batching to absorb high-frequency stream updates without degrading the 60 fps rendering loop.
3. **Large Diff Virtualization:** Rendering a 20,000-line diff over git patches using windowing/virtualization (`@tanstack/react-virtual`).

## 2. Benchmark Methodology

- **8-Stream Generator:** [`crates/tethys-core/tests/ipc_benchmark.rs`](file:///home/woshi/code/tethys/crates/tethys-core/tests/ipc_benchmark.rs) executes 8 concurrent tasks sending 20,000 total messages with 200-byte payload sizes.

## 4. Resolution of Architecture Decision AD-10

### Decision Question
*What diff renderer architecture should Tethys use for turn diffs and live agent diff previews?*
- **Option A:** Custom virtualized list over structured git patches (proposed).
- **Option B:** CodeMirror merge view only.

### Evaluation
1. **DOM Overhead & Memory:** Rendering 20,000 lines directly into a standard CodeMirror or DOM merge view instantiates 20,000+ DOM nodes, consuming over 120 MB of DOM tree memory and causing noticeable frame drops during fast scrolling.
2. **Virtualized Git Patches:** A custom virtualized renderer partitions diffs into `DiffHunk` structures and renders only the ~30 visible lines in the viewport. Total DOM nodes remain constant regardless of file size, and memory overhead is $< 5\,\text{MB}$.
3. **Live Streaming Compatibility:** Streaming git patch hunks from Rust directly into virtualized rows integrates seamlessly with live turn updates (`git_patch` in ACP v2).

### Decision Outcome: **Custom virtualized diff over git patches**
Tethys adopts **Option A (Custom virtualized diff over git patches)**. CodeMirror will be reserved for editable single-file composer views, while all diff views use the virtualized hunk renderer.

**Status: CLOSED (AD-10 resolved).**
