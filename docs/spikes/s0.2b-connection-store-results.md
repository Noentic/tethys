## 1. Context & Architecture

Spike S0.2b addresses agent lifecycle economics based on learnings from Zed (PR #62922 and `ARCHITECTURE.md §6.2`). Coding agents consume significant memory (150 MB – 500 MB per process). Spawning a dedicated process per thread quickly leads to host memory exhaustion when users manage dozens of concurrent threads.

`ConnectionStore` implements:
1. **Pooled Connections per Agent Profile:** Threads targeting the same agent profile share a connection when concurrency permits, tracked via reference-counted `LeaseToken`s.
2. **Two-Phase Reaping:** When a thread completes a turn and drops its lease, the connection transitions to `Draining`. If no new leases are acquired within a configurable grace period, the agent process is terminated.
3. **Transparent Recovery on Disconnect:** If an agent process crashes or its transport closes unexpectedly during active lease usage, the next prompt automatically re-spawns and recovers the connection.

## 2. Verification Results

The test suite in [`crates/tethys-core/tests/connection_store.rs`](file:///home/woshi/code/tethys/crates/tethys-core/tests/connection_store.rs) verified:
1. **Lease Sharing:** Multiple concurrent threads on `claude-code` acquired leases while sharing a single underlying connection instance (`total_spawns = 1`).
2. **Idle Reaping:** Dropping the last lease transitioned the connection to `Draining`. After the 50 ms test grace period, `reap_idle()` terminated the connection (`status: Terminated`), leaving **zero resident idle agents**.
3. **Crash Recovery:** Marked connection disconnected (`mark_disconnected`). The subsequent `acquire_lease()` transparently revived the connection (`status: Connected`, `restart_count: 1`, `total_spawns: 2`).

## 3. Resolution of Architecture Decision AD-4

### Decision Question
*Should Tethys allocate an agent process per thread or pool processes per profile using leases?*
- **Option A:** Dedicated process per thread.
- **Option B:** Pooled per profile with leases (Zed-style, proposed).

### Evaluation
- **Process per Thread:** Heavy RSS footprint (~1.2 GB for 4 threads); high startup latency on each thread creation.
- **Pooled per Profile with Leases:** Minimal steady-state footprint; fast prompt start times; automatic reclamation of idle agents via two-phase reaping.

### Decision Outcome: **Option B (Pooled per profile with leases)**
Tethys adopts **Option B (Pooled per profile with leases)**. All agent processes are managed through `ConnectionStore` with automatic idle reaping and transparent restart on transport drops.

**Status: CLOSED (AD-4 resolved).**
