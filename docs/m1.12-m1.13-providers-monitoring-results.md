## 2. Delivered Surface

- **Store and API.** `AgentProfileRow` persistence and a hot-cache hydrated at `Core::open`; the whole
  `agent.*` namespace typed end to end (`agent_process_sample`, `agent_health_interval_set` and
  `agent_recheck` are new methods beyond the §12.1 list); `agent.config_*` stays `Unimplemented` (M2.5).
  `agent.env_secret_set` is write-only: the value goes to the keychain, the profile keeps a
  `keychain:tethys/profile/<id>/<KEY>` reference, and the agent's launch resolves it (`EnvResolver` on
  `StoreOptions`; a missing secret stops the launch). Documented in architecture §12.1 and
  pages-views-spec §5.2.
- **Registry engine.** `crates/tethys-agent-servers/src/registry`: published-schema model tolerant of
  unknown fields, a `RegistrySource` seam, per-distribution install (`npx`, `binary` with `.zip` and
  `.tar.gz`), platform key mapping, compliance notes, `semver` update detection.
- **Cancel phases.** `thread.cancel` emits `cancel_requested{grace_deadline}` on the existing event
  stream, `grace_elapsed` when the window closes, and `terminating` on the explicit second press. The
  webview applies them (`sessionReducer`); `AppShell` forwards every Stop press to `thread.cancel` and
  keeps no clock of its own.
- **Health.** One `recheck`, seven call sites: the interval tick (armed at `Core::open` to 300 s; `0`
  disarms), `↻` (all enabled), login-surface close, executable-path edit, runtime toggle-on (both through
  `agent.profiles_update`), cold start (`Core::open`), and network reconnect (the webview `online` event;
  active while Settings / Providers is mounted). Six have a test that fires them; for the interval tick
  the tests assert that it is armed and disarmed, not that it fires, because that needs a wall-clock
  wait (it calls the same `recheck_all` as `↻`). A profile the user has switched off is skipped by every
  sweep.
- **Monitor.** `Monitor`, a pull-based sampler with per-tree state (see §3).
- **UI.** `packages/features/src/agents` (rows, accordion, capabilities panel, stderr viewer, login
  surfaces, profile cards, launch-spec editor, header) and `packages/features/src/monitor` (activity
  table); `@tethys/state` provider store with the swap-point names for worktrees C and F.

## 3. Monitoring overhead (MON-01)

Measured with `cargo bench -p tethys-core --bench monitor_overhead`: a three-process tree sampled
15 times on the architecture §7.5 cadence (2 s), reporting this process's own CPU time as a share of
wall time. Machine: the author's Linux workstation, 1,117 processes running, load average ≈ 1.

| Implementation | Per-sample wall time (mean / p95) | Sampler CPU | Overhead | Budget |
|---|---|---|---|---|
| First cut: refresh every process on every sample | 48.69 / 50.95 ms | 730 ms over 30 s | **2.433%** | **FAIL** |
| Shipped: refresh known members each sample, machine-wide discovery every 5th | 13.57 / 66.15 ms | 200 ms over 30 s | **0.667%** | **PASS** (< 1%) |

The first cut failed its own criterion, so it was changed rather than the budget. The bench was run
twice for that reason only; the figure recorded here is the second run and it is not re-run (AGENTS.md).
CI keeps only the deterministic tree-enumeration tests.

### Idle core footprint

Measured once with `cargo bench -p tethys-core --bench idle_core_rss`: `Core::open` as the app does it
(store, hydrated profiles, health poller armed at 300 s, monitor constructed), eight registered
profiles, no thread running, five seconds settled, release profile.

| Metric | Result | Architecture §9 target |
|---|---|---|
| Core RSS, idle | **9.1 MB** (5.3 MB before `open`) | ≤ 50 MB (hard) |

This is the core process only, measured in a bench harness: it excludes the Tauri host and the webview.
The S0.8 spike recorded ≈ 24 MB for a different scope; the two are not compared here.

**Trade-off, stated plainly.** Between discovery scans only known members are refreshed, so a child
that starts *and exits* between two scans (up to about 10 s at the 2 s cadence) is never observed. The
leader row's tree-summed CPU/RSS under-counts such a child. Longer-lived children are picked up on the
next scan.

## 4. Defects found and fixed while closing the chunk

1. **`credential_principle` fork bomb (test-harness, severe).** The audit's profile launched
   `current_exe()` without `TETHYS_MOCK_ACP`, so each spawned child re-ran the whole audit and spawned
   another. It reached about 2,800 live processes and about 55,000 threads and starved the machine,
   which surfaced as tokio's `OS can't spawn worker thread (os error 11)` in every other terminal.
   Killing children triggered respawns from their parents, so the tree had to be frozen (`SIGSTOP`)
   before it could be killed. Fix: the profile now sets `MOCK_ENV`; and `tethys_acp::mock::run_if_requested`
   gained a re-exec guard (`TETHYS_TEST_HARNESS`, exit code 97) so any harness that forgets `MOCK_ENV`
   fails in one line instead of multiplying. Every re-exec harness inherits the guard with no call-site change.
2. **CPU always read `0.0`.** `sysinfo` derives CPU from the delta between two refreshes of the same
   `System`; the sampler built a fresh one per call. `Monitor` now keeps one `System` per tracked tree
   (a shared one, partially refreshed, would skew the delta between trees). The first sample of a tree
   still reports 0 CPU by construction.
3. **Login countdown reset on every keystroke.** The default code deadline was recomputed on each
   render. It is now fixed at mount.
4. **Code expiry did not re-check the Provider.** Expiry is a listed close route; the view never passed
   `onExpiry`. It now re-checks that Provider.
5. **Only 5 of the 7 re-check triggers were wired.** Cold start and network reconnect had no callers,
   and the poller was never armed (backend interval `0` while the UI showed 300 s), so out of the box
   nothing polled and the screen misreported it. `Core::open` now arms the default interval and runs
   one check; the view listens for `online`.
6. **Disabled profiles were spawned by health sweeps.** The sweep set was every registered profile; the
   row's `enabled` flag never reached it. A switched-off Provider would be launched by the interval
   poller and by `↻`. `ThreadSessions::set_profile_enabled` now feeds the sweep set.
7. **A not-found check recorded no time.** Both `NotFound` branches left `last_checked_ms` unset, so a
   check that ran looked like it never had.
8. **A unit test ran a real `npx -y <package>`.** Installing an `npx` registry entry re-checks the
   Provider; with Node installed, `agent_api.rs` fetched and executed the real vendor package (5.5 s,
   network). The test now runs with an empty `PATH` (0.06 s) and asserts the `needs Node.js` state.
9. **A profile edit never reached the connection store.** `ConnectionStore::register` used
   `or_insert_with`, so the first registration of a profile won for the life of the process. Editing a
   profile's executable, args or env did not take effect until restart; an opt-in registry update
   re-pinned the database row while the old version kept launching; and a saved API key was written to the
   profile but never launched with it. `register` now replaces the spec of a registered profile, and
   `retire_idle` drops an unused connection so the next check spawns with it; a connection in use is
   left running.
10. **The real cancel phases never reached the UI.** `sessionReducer` had no `CancelPhaseChanged` case,
    and `AppShell` ran a client-side fixture timer on Stop instead of calling `thread.cancel`, so the
    second press (`Force kill`) could not work. The reducer now applies the backend's phases and
    `AppShell` forwards every press.
11. **`cancel` could stick in `cancel_requested`.** If the protocol cancel failed to send, the grace timer
    had not been armed yet, and a second press is ignored in that phase. The timer is now armed first.
12. **The env-var login flow stored nothing and nothing resolved it.** It emitted a reference to a
    keychain entry that was never written, in a format (`keychain:profiles/…`) that matched neither the
    spec nor `tethys-sync`, and agent launches passed `keychain:` values through verbatim. Completed as
    described in §2; the value field is now masked.
13. **Activity table.** Restart always restarted the first Provider and the table never received a cancel
    phase; samples were also delayed one interval after mount because the first sample ran before the
    profile list had loaded. Tables are now per Provider, and sampling re-runs when the enabled set changes.
14. **Deleting a profile left its keychain secrets behind.** It now deletes those it owns.
15. Dead `intervalSeconds`/`onIntervalChange` props on `ProvidersHeader` (the real control is
    `HealthIntervalControl`), a redundant `role="table"`, the client surface assertion missing four
    agent keys, and two clippy findings (`BackendClass::from_str` renamed `parse`; an eight-argument
    `row_from_input` became a `ProfileDraft`).

## 5. Not done, and open decisions

- **Idle webview RSS against architecture §9 (≤ 120 MB macOS/Linux, provisional) was not measured.** It
  needs the packaged release app with a window on screen. The S0.8 spike measured the webview *bundle*
  (378 KB), not its RSS. Core idle RSS is measured (§3). Measure the webview once on the integrated
  build at the Wave 2 checkpoint; this chunk's only webview addition is the Settings / Providers screen.
- **The env-var secret flow reads its value into the webview once**, in the masked field, before handing
  it to the host, and then clears it. That is unavoidable for a form the user types into. Which G7
  reading applies (a user-typed API key for their own agent, kept as a keychain reference, versus a
  vendor login token Tethys must never touch) is stated in pages-views-spec §5.2, and it matches how MCP
  secrets are already handled; if product prefers the stricter reading, the env-var method should
  accept only references.
- **An edit applies to the next start of a connection that is in use.** An unused connection is retired
  so the following check reflects the edit; one serving a running turn is left alone, and `Restart`
  applies the edit to it.
- **`agent.logout`** is a stub (delegated to the vendor CLI), as planned.
- **Live capability re-check** is V1 (spec §5.2 clause 5); the panel shows the last negotiated snapshot.
- **`elicitation`** resolved the plan's open question in favour of `NormalizedCapabilities`: M1.7 added
  the field on trunk, so the panel reads it directly and no per-profile snapshot exists. Its meaning is
  "Tethys advertised form elicitation on this connection", not an agent-declared capability.
- **Real vendor binaries** are Wave 2.5 (M1.18–M1.20); nothing here connects a real CLI.
- The milestone row for M1.13 says "footprint budget assertions in CI". Per the plan and AGENTS.md this
  is a one-time bench plus deterministic correctness tests, not a per-run budget assertion.

## 6. Deviations from the plan

- `agent_profiles` was pre-allocated by M1.6d's migration `0005` (D14); this branch adds no migration.
- Neither `@tanstack/react-table` nor `@tanstack/react-form` was added (the D5 answer).
- The M1.6c second-press question resolved to an explicit, interactive `Force kill`: the grace timer
  advances `cancel_requested` → `grace_elapsed` on its own, but the destructive step waits for the user.
- `Monitor` refreshes only known members between scans, where the plan said only "refresh that process
  set"; discovery needs a machine-wide read, so it is periodic (§3).
