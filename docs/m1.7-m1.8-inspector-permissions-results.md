## 3. Decisions

- **Policy is a Rust choke point.** Every ACP request flows through `PermissionResolver`; the webview only renders a decision and returns the user's `option_id`. A widening bug cannot be introduced from the webview.
- **Auto-edit needs a path.** The resolver's `File` subject is derived from an edit-kind tool call's first location in the transport mapper, so Auto-edit is functional rather than dormant.
- **The inbox is a projection.** `selectInboxItems` aggregates the per-session `pendingPermissions`/`pendingElicitations` — one source of truth shared with the inline cards.
- **Two cards, two entry kinds.** `permission_request` and `elicitation` are distinct registry keys; the "never renders for a non-elicitation Provider" guarantee is a backend gate, not a render-time branch.
- **Runs group only when > 1.** A single tool call stays an individual accordion, so per-turn actions and the existing composition contract are unchanged.
- **Subagent nesting is one level.** Grandchildren render flat inside the first card with a `depth 2` marker.
- **Turn endings are materialized, not inferred.** The reducer appends a `turn_notice` entry from the stop reason (and the `Error` event), so the renderer is a plain entry renderer.

## 5. Deviations / Limitations

- **The two performance exit criteria are not measured here.** Byte-to-paint p95 and 10k-entry 60 fps need a real browser paint/scroll harness that this environment does not provide. The architectural mitigations (worker boundary, block-hash cache, tail-pinning) are in place and `streamdown` is the recorded fallback. This is the one honest gap in M1.7.
- **`provider_artifact` has no producer yet.** The renderer is registered and fixture-tested; Wave 2.5's Provider adapters emit the entry. `provider-popover` is likewise fixture-only, with the stream→queue wiring in `InspectorScreen` ready for the real `ProviderExtension` events.
- **M1.6c landed before this chunk**, so the plan's "two shell edits" were already replaceable defaults and no shell file was edited.
- **`ProviderExtension` stream wiring enqueues only methods with a registered surface**; unregistered methods fall through to generic rendering, as designed.
- **Residual security notes** from the review remain documented: a tiny emit-before-park window in the ACP handlers, Windows path case-sensitivity in `starts_with`, elicitation value validation delegated to the Provider, and mode not persisted across process restarts.
