## 2. AD‑9 Gate

**Decided: TipTap / ProseMirror**, behind the `EditorHandle` interface in `@tethys/composer`.

- Editor dependency (`@tiptap/{core,pm,react,suggestion}`) was already landed by the M1.6d conditional batch, so U1's measurement confirmed the pre-decided choice rather than reopening it.
- Harness: `packages/composer/src/editor-gate.bench.ts`, run once via `pnpm --filter @tethys/composer bench` (not in CI, not in the barrel). It drives the real TipTap/ProseMirror editor: the popup number types `/rev` through the actual `@tiptap/suggestion` pipeline wired to an instant stub source, and the paste number sets a 1 MB document and serializes it.
- Measured on the author's machine (this checkout): trigger → first popup result **1.9 ms**; 1 MB paste + serialize **4.2 ms** (repeat runs 1.1–1.9 ms / 2.2–4.2 ms).
- `docs/architecture.md` §15 AD‑9 now reads **Decided** with these numbers.
- **Deviation:** the plan's risk note asks for a real-`tauri dev` rAF/compositor sample and says to fall back to the textarea if it cannot be taken. The compositor smoke under WKWebView/WebView2/WebKitGTK was **not** run in this environment; the recorded numbers are the engine-path proxy. The textarea+chip-strip fallback (`EditorHandle` makes it swappable) remains the safety net; the WebView smoke stays a follow-up.

## 3. Prompt Queue Persistence

- A queued prompt is an event on its thread's own log: `thread.queue.add|remove|reorder` (`NewEvent`, `entry: None`), appended through the public `EventStore::append_batch` facade. **No new migration or table in `crates/tethys-store`** (§1.2's cross-crate rule honoured).
- `crates/tethys-core/src/thread_queue.rs` re-materializes the queue by folding the log (`q-<seq>` is the item id). `EventStore::open` on the same file re-reads it after a drop → the "survives app restart" criterion.
- `QueuedPrompt` wire type: `crates/tethys-schema/src/queue.rs` (+ one `pub mod`, one `registered_types` line).
- The queue UI (`packages/features/src/composer/queue.tsx`) is edit/reorder/remove over that namespace; `@tethys/state`'s `createPromptQueueStore` wraps it testably.

## 7. Review fixes

- **Double submit (fixed):** `PromptCard`'s send control is `type="submit"` inside the card `<form>` and also carried an `onClick`, so one click ran `submit()` twice (once from `onClick`, once from the form submit), creating two threads. The `onClick` is removed — the form's `onSubmit` is the single path — with a regression test asserting the send button starts exactly one session (`prompt-card.test.tsx`).
- **Queue ordinal (fixed):** `thread_queue::add` returned `ordinal: 0` for every append; it now returns the item's real zero-based position, asserted in `thread_queue_tests.rs`.

## 8. Limitations / Follow-ups

- **Real-WebView compositor smoke** (AD‑9) not run; engine-path proxy recorded (see §2).
- **`thread.setConfigOption` is typed at the boundary but `tethys-core` returns `Unimplemented`** — the ACP `session/set_config_option` send and the per-Provider config-schema read are M1.12/E's, per the plan. UI tests mock the client; `ComposerConfigChips` reverts and shows the capability notice on rejection.
- **Action-bar wiring:** the shell (M1.6c) renders `queue-count` natively from the `queueCount` prop at DESIGN's priority, and passes only `sessionId` to registered slots. The composer registers `queue-count` (id-only) and the `mode` pill; the live data path for the registered slots is the Wave 2 checkpoint's. No shell file was edited.
- **Queue edit reopens in the editor:** `thread.queue.*` has add/remove/reorder only, so an "edit" reopens the item in the composer (`onEdit`) and re-stages it; there is no in-place `queue.update`. Fine for MVP; add one if a queued item must be patched without re-staging.
- **Docked composer in `/thread/:id`:** the queue/composer components are built and tested; mounting them in the inspector stage is adjacent to M1.7's `InspectorScreen` and was left to the checkpoint rather than editing a landed chunk's file.
- **File-drop → `@`-chip** uses the search-backed source for typed `@`; a rich/file drop inserts an `@`-named chip with a client-side token (no server resolution). V1 polish.
- The fixture hooks and the deleted mocks are the exact two swap points named in D12; nothing else in this chunk is fixture-bound.
