## 3. The five cell states

`mcp.attachments` is authoritative; `renderCellState` maps a returned `AttachmentState` to a view descriptor and does no capability logic. A `satisfies Record<AttachmentState["kind"], …>` key set plus a `never` switch default make a schema change a compile error.

| Variant | Cell | Tone |
|---|---|---|
| `Attached` | `Attached` | `status-success` |
| `UnsupportedTransport { needs }` | `Unsupported transport` + `needs <transport>` | `status-warning` |
| `FileProjection { target, state }` | `File projection` + projection sub-state (`pending` muted / `in-sync` success / `drifted` warning / `conflict` danger / `unsupported` muted); activating opens the fallback section | per sub-state |
| `Excluded` | `—` | muted |
| `NotNegotiated` | `not connected` (never `Attached`) | muted |

`attachment-cell.test.tsx` renders all five; `not-negotiated` is asserted never to read `Attached`. A cell is a fact or the fallback action, never both (DESIGN P13): `actionable` is true only for `FileProjection`.

## 4. Decisions

### D5 — `@tanstack/react-table` on the MCP surface

Used, as `architecture.md` §5.1 assigns and overview D5/D7 decide. The installed major is **v9** (`9.2.4`), whose API differs from the v8 examples the plan was written against: `useTable` + `tableFeatures({ columnPinningFeature })` + `createColumnHelper<typeof features, TData>()`, pinning expressed as `start`/`end`, and cell values read through the accessor model (`row.getValue(columnId)`). It supplies the ordered column model over an unbounded Provider set and the pinned `server` column (`getStartVisibleLeafColumns` / `getCenterVisibleLeafColumns`); the component still owns all markup, the `position: sticky` styling and the whole roving focus model, because a table library gives structure, not keyboard behaviour. This is the plan's stated division, realised against v9 rather than v8.

### Presentation follows §5.4 as decided

The matrix, `grid`/`columnheader`/`rowheader`/`gridcell` roles, the frozen `220px` server column, the `132px` minimum column width, the sticky header, horizontal scroll inside the region, and the two empty states (`No MCP servers configured` keeps the header; `No connected Providers` keeps the frozen column and links to Settings / Providers) are implemented as DESIGN.md `d0-rc5` specifies; nothing in §5.4 needed an edit. The workspace is the page's scope selector, not a third axis.

### Projection is structurally separate

`ProjectionFallback` renders only when `hasFallbackProjection(grid)` is true, under the header "Vendor-file fallback", and is the only place with `Preview diff` / `Apply` / `Rollback`. The import wizard, the server card and the grid carry no apply step. Apply passes the previewed plan back to `mcp.projection.apply`, which re-derives it server-side; a mismatch surfaces as "workspace changed — re-plan and retry", never a silent overwrite.

### Trust is content-bound

The trust control appears only for `requires_trust` skills; `skills.trust` returns the persisted `SkillInfo` and the row reads it back. Applying an update clears trust (`update_apply` in the engine), and the row reflects `trusted:false`. The YOLO exclusion of untrusted script skills is *displayed* ("Untrusted script skills are excluded from YOLO threads"), not enforced here — enforcement is M1.8.

## 5. Grid behaviour

- Roving: one `tabindex=0` for the grid, on the first `gridcell` on entry and the last-focused cell thereafter; arrows move one cell and clamp without wrapping; `Home`/`End` are the row's ends; `Ctrl+Home`/`Ctrl+End` the grid's corners; `PageUp`/`PageDown` by the visible row count; `←` from the first `gridcell` reaches the `rowheader`; `Tab` is not handled, so it leaves the grid. Covered by `use-grid-roving.test.ts` (pure model) and `sync-grid.test.tsx` (DOM).
- Twelve Provider columns render inside the `overflow-x-auto` scroll region with `scroll-padding-left: 220px`; the page container never scrolls horizontally (`sync-grid.test.tsx`). This is a settings page, not a streaming surface, so column virtualization stays deferred (plan Deferred).
- Two empty states, with the zero-columns state winning when both axes are empty.
- Provider header state goes through the shared `StatusDot` (D11), asserted by role and `aria-label` (`Healthy` / `Not found`), never a chunk-local dot.
- One grid render path serves all three shapes, so the empty states are siblings of the `role=grid` element (not children) and the frozen column keeps a real `role=row` parent; axe flagged all three anti-patterns during review and the fix is covered by the axe test.

## 6. Deviations

- **react-table v9 rather than the v8 examples in the plan.** The plan's snippet-level assumptions (`useReactTable`, `columnPinning.left`, `getLeftVisibleCells`) do not exist in the installed major; the equivalent v9 APIs are used. No product decision changed.
- **`grid` roles on `div`s.** DESIGN mandates `role=grid`/`row`/`columnheader`/`rowheader`/`gridcell`; Biome's `useSemanticElements` prefers native table elements. Followed the existing codebase convention (`biome-ignore` per element, as `segmented-control` / `session-list-row` do) to keep the DESIGN roles and the sticky/scroll layout. The server `rowheader` is a `<div>` rather than a `<button>` because `rowheader` is not an allowed role on a button (axe `aria-allowed-role`); it keeps its roving `tabindex` and Enter/Space activation.
- **Axe coverage extended to the new surfaces.** `apps/desktop/src/a11y.test.tsx` gained MCP and Skills cases; it caught three structural ARIA bugs in the first grid layout (rowheader-on-button, empty state inside `role=grid`, and the zero-column branch's headerless rowheader) that the unit tests did not.
- **Skills category pill.** `SkillInfo` carries no category field, so the `category-pill` slot shows the skill's `source.origin` (folder / archive / git-hub / lockfile) rather than an invented taxonomy.
- **Search box omitted from Settings / Skills.** Not in R6; the previous shell's search was mock-data-only. YAGNI for MVP; additive later.
- **No column virtualization, no `Discover` remote catalog** — both deferred in the plan.
- **§5.4's UX-flow phrase "clicking `Apply All`" is realized as a per-target `Apply`.** The component list in the same section specifies `Preview diff → Apply → Rollback`, and the projection unit is one `(target, scope)` file, so the fallback section renders one row per target with its own actions; there is nothing to bulk-apply. The §5.4 block already reads "Decided", so it is noted here rather than edited.
- **`mcpWorkspaceScope` is fixture-backed** (`useMcpWorkspaceScope`), swapped for F's trust-filtered `workspace.list` at the Wave 2 checkpoint (D12).
